# Рок-группа — личный кабинет музыканта (ДЗ9, вход по JWT)

Домашняя работа 9 по веб-технологиям. Тот же сайт рок-группы, что и в ДЗ8, но
авторизация переписана с сессионной куки на **два токена JWT**. Одностраничное
приложение на React + TypeScript. Бэкенд предоставлен преподавателем.

Живая версия: https://LOGIN.github.io/rok-gruppa/
Сервер: `https://inai-col3.fishrungames.com` (в ДЗ8 был `inai-col2`).

## Что умеет

- регистрация нового музыканта (логин и пароль от 6 символов);
- вход и выход;
- просмотр своего профиля: имя, специализация, рассказ о себе, гонорар;
- редактирование профиля, специализация выбирается из списка, который отдаёт
  сам сервер;
- сессия переживает перезагрузку страницы: пропуск выписывается заново
  автоматически;
- человеческие сообщения об ошибках вместо кодов.

## Авторизация на двух токенах

Сервер выдаёт два токена, и у каждого своя работа.

**access** — короткий пропуск. Живёт **ровно 5 минут** (это видно внутри самого
токена: `exp - iat = 300`). Приходит в теле ответа на `/api/register/` и
`/api/login/`, дальше кладётся в заголовок `Authorization: Bearer <access>`.
Хранится **только в памяти вкладки**, в переменной. В `localStorage` его не
кладут: туда может залезть любой посторонний скрипт на странице, а пропуск —
это и есть право действовать от имени пользователя.

**refresh** — долгий, на 7 дней. Его нам вообще **не показывают**: сервер кладёт
его в куку `refresh_token` с пометкой `HttpOnly`, то есть из JavaScript она не
читается. Браузер подставляет куку сам, но только если в запросе разрешена
отправка кук — отсюда `credentials: 'include'` в **каждом** обращении к серверу.
Без этой строки обновление пропуска отвечает «Cookie refresh_token не найден».

### Почему обновление встроено в запрос, а не висит на кнопке

Пять минут — это очень мало. Человек открывает профиль, задумывается над
«о себе», жмёт «Сохранить» — и получает отказ на ровном месте. Поэтому
обновление спрятано внутрь функции `запрос`:

```
запрос → ответ 401 → сходить за новым пропуском по куке → повторить запрос
```

Повтор ровно **один**: если refresh-кука и правда просрочена, второй заход
ничего не изменит, а вечный круг запросов получился бы мгновенно.

После перезагрузки страницы пропуск теряется — он лежал в памяти. Но кука
никуда не делась, поэтому первый же запрос профиля получает 401, сам продлевает
пропуск и возвращает пользователя в кабинет. Отдельного «восстановления сессии»
писать не пришлось: оно получилось само из этого правила.

## Две особенности сервера, которые пришлось обойти

Обе найдены опытами и обе воспроизводятся.

### 1. Занятый логин возвращает 500 и HTML вместо JSON

Регистрация на существующий логин отвечает не «400 + объяснение», а страницей
`Server Error (500)`. Обычный код делает `response.json()`, спотыкается о HTML и
валит всё приложение в белый экран. Поэтому разбор тела обёрнут в `try`, а на
связку «500 + адрес регистрации» показывается понятное «Такой логин уже занят».

### 2. Выход на сервере не доводится до конца

`POST /api/logout/` отвечает «Успешный выход», но:

- **куку не стирает.** Удаляющий заголовок приходит без пометок `Secure` и
  `SameSite=None`, а ставилась кука именно с ними. Сайт и сервер на разных
  доменах, и такое удаление браузер отвергает — кука остаётся на месте;
- **refresh не отзывает.** Старый токен после выхода по-прежнему выдаёт новые
  пропуски (проверено напрямую запросом).

Вместе это значит, что после «Выйти» и нажатия F5 человек снова оказался бы
внутри своего аккаунта. На чужом или общем компьютере это дыра.

Чинить сервер мы не можем, поэтому выход держится на своей стороне: при выходе
в `localStorage` ставится метка, она переживает перезагрузку, и пока её не
сняли, приложение не восстанавливает сессию и не продлевает пропуск. Снимается
метка при следующем успешном входе или регистрации.

## Проверено

Весь поток прогнан в настоящем браузере (Chromium, Playwright), 9 проверок:
регистрация → правка профиля → перезагрузка страницы → выход → перезагрузка
после выхода → неверный пароль → повторный вход → занятый логин. Гонорар
вводился с запятой («2500,50») — форма сама меняет её на точку, иначе сервер
отвечает «Требуется численное значение».

## Запуск

```bash
npm install
npm run dev      # разработка
npm run build    # сборка в dist/
npm run preview  # посмотреть собранное
```

Публикация на GitHub Pages — автоматически при push в `main`
(`.github/workflows/deploy.yml`). Имя репозитория должно совпадать со строкой
`base` в `vite.config.ts`, иначе страница откроется пустой.
